# 웹 실행 주소와 배포

최신 게임은 아래 링크에서 설치 없이 실행한다.

**https://kohyuji.github.io/cat-at-the-door/codex-v5/**

기존 공개판 주소인 `https://kohyuji.github.io/cat-at-the-door/`도 유지한다.

## 수정한 게임을 올리기

Node.js와 Git이 설치돼 있고 GitHub에 로그인된 환경에서, 저장소 폴더의 터미널을 연다.

1. 게임을 수정하고 `npm test`로 검사한다.
2. 변경 파일을 커밋한 뒤 `git push origin HEAD:codex-v5`로 소스를 올린다.
3. `npm run deploy`를 실행한다.
4. 출력된 배포 요청이 끝난 뒤 실행 링크에서 새 버전을 확인한다. GitHub Pages 반영에는 잠시 시간이 걸릴 수 있다.

`npm run build`는 실행에 필요한 파일을 `dist/`에 모은다. `npm run deploy`도 빌드를 먼저 실행한다. 배포하지 않고 묶음만 검사하려면 `node tools/deploy-pages.cjs --prepare-only`를 쓴다. 이 옵션은 푸시하거나 GitHub 설정을 바꾸지 않는다.

## 브랜치의 역할

| 브랜치 | 용도 |
| --- | --- |
| `codex-v5` | 최신 게임 소스와 설명서 |
| `main` | 기존 공개판 소스. 이 배포 도구는 수정하지 않는다. |
| `gh-pages` | 웹에 올릴 파일만 담는 자동 생성 브랜치. 직접 수정하지 않는다. |

배포할 때마다 `main`의 현재 파일을 `gh-pages` 루트에 그대로 복사하고, 최신 게임을 `codex-v5/` 하위에 넣는다. GitHub Pages는 `gh-pages`의 루트를 서비스한다. 따라서 기존 공개판과 새 게임을 다른 주소로 유지하면서 `main` 자체는 건드리지 않는다.

`main`에 푸시하는 것만으로 공개판이 즉시 바뀌지는 않는다. 다음에 `npm run deploy`를 실행할 때 `main`의 최신 내용도 공개판 주소에 함께 반영된다.

`dist/`는 자동 생성 파일이므로 직접 고치거나 커밋하지 않는다. 배포용 임시 파일은 시스템 임시 폴더의 `cat-at-the-door-pages/` 아래에 만들고 사용 후 정리한다. GitHub 인증 정보는 정상 Git 로그인을 통해 메모리에서만 사용한다. 브라우저를 열거나 컴퓨터 화면을 조작하지 않는다.
